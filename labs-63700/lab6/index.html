What This Lab Is About

Due: Friday, Feb. 26, 2027.

In this lab you change images with pointwise operations. A pointwise operation maps each gray level to a new gray level, and the new value of a pixel depends only on its old value. Pointwise operations are an important class of methods for image enhancement.

In Module 1 you compute the histogram of an image, which shows how its gray levels are distributed. Then you enhance an image in two ways: by histogram equalization, which maps the gray levels through their own cumulative distribution, and by contrast stretching, which maps a range of gray levels onto the full range. In Module 2 you measure the gamma of your own display, which describes how the display turns gray levels into light. Then you use it to gamma correct an image stored on a linear intensity scale, and to convert an image that was corrected for a different display.

Step 1: Set Up lab6.py

Copy these helpers into lab6.py. load_image and save_image read and write 8-bit images as uint8 arrays. to_uint8 rounds real gray levels and clips them to 0 to 255. apply_table applies a pointwise operation that is given as a table of 256 values. 

import numpy as np
from PIL import Image


def load_image(path):
    """This function reads an 8-bit grayscale image file and returns it as an array.

    path     path to a PNG or TIFF file
    returns  (H, W) uint8 NumPy array with integer gray levels 0 to 255
    """
    return np.asarray(Image.open(path).convert("L"), dtype=np.uint8)


def save_image(x, path):
    """This function writes an (H, W) uint8 array as an 8-bit grayscale PNG.

    x        (H, W) uint8 NumPy array
    path     output file name, ending in .png
    """
    Image.fromarray(np.asarray(x, dtype=np.uint8)).save(path)


def to_uint8(y):
    """This function rounds an array of gray levels and clips it to 0 to 255.

    y        NumPy array of real gray levels
    returns  uint8 NumPy array of the same shape
    """
    return np.clip(np.round(y), 0, 255).astype(np.uint8)


def apply_table(x, table):
    """This function applies a pointwise operation given as a table of 256 values.

    Pixel x[m, n] of the output is table[x[m, n]].

    x        (H, W) uint8 NumPy array
    table    NumPy array of 256 values, one for each gray level 0 to 255
    returns  (H, W) array with the type of table
    """
    table = np.asarray(table)
    if table.shape != (256,):
        raise ValueError("table must have 256 entries")
    return table[x]

table[x] uses the array x as a list of indices into table, so one NumPy operation looks up every pixel.

Step 2: Histograms

Let \(S\) be the set of pixel locations, and let \(X_s\) be the gray level at the pixel \(s \in S\). The gray levels take the values \(0, \dots, L-1\) with \(L = 256\). The histogram of the image counts the pixels at each gray level,

$$ h(i) = \sum_{s \in S} \delta(X_s - i) \ , \qquad i = 0, \dots, L-1 \ , \tag{1} $$

where \(\delta(0) = 1\) and \(\delta(k) = 0\) for \(k \neq 0\). 

def histogram(x):
    """This function returns the histogram of an 8-bit image.

    x        (H, W) uint8 NumPy array
    returns  (256,) int64 NumPy array h, where h[i] is the number of pixels
             with gray level i
    """

histogram does not call np.histogram, because the check below uses it.

Step 3: Histogram Equalization

Histogram equalization transforms an image so that its histogram is spread uniformly over the full range of gray levels. To see how, think of the gray level of a pixel as a random variable \(X\) with cumulative distribution function \(F_X(x) = P\{X \le x\}\). Map \(X\) through its own distribution function to form \(Y = F_X(X)\). If \(F_X\) is continuous and increasing, then for \(0 \le y \le 1\)

$$ P\{Y \le y\} = P\{X \le F_X^{-1}(y)\} = F_X\big(F_X^{-1}(y)\big) = y \ , $$

so \(Y\) is uniformly distributed on \([0, 1]\). The histogram of an image can therefore be equalized by mapping each pixel through the distribution function of its gray levels.

The distribution function is estimated from the histogram by the empirical CDF,

$$ \hat F_X(i) = \frac{\sum_{j=0}^{i} h(j)}{\sum_{j=0}^{L-1} h(j)} \ , \qquad i = 0, \dots, L-1 \ . \tag{2} $$

The denominator makes \(\hat F_X(L-1) = 1\). The values \(Y_s = \hat F_X(X_s)\) lie between 0 and 1, but they do not start at 0. Let \(Y_{\min}\) and \(Y_{\max}\) be the smallest and largest values of \(Y_s\) over the image. The equalized image is

$$ Z_s = (L-1) \, \frac{\hat F_X(X_s) - Y_{\min}}{Y_{\max} - Y_{\min}} \ , \tag{3} $$

rounded to the nearest integer.

Step 4: Check the Equalization

If the histogram of an image were exactly flat, then its empirical CDF would be the CDF of a uniform distribution on the gray levels 0 to 255, which is the straight line \((i+1)/256\). The distance of the empirical CDF from this line measures how far the histogram is from flat:

$$ D = \max_{0 \le i \le 255} \left| \hat F(i) - \frac{i+1}{256} \right| \ . $$

Task 4a. Compute \(D\) for kids.png and for its equalized image. Plot both empirical CDFs and the straight line on one graph.

Task 4b. Count the distinct gray levels in kids.png and in its equalized image. Confirm that the equalization is a pointwise operation that does not decrease: every pixel with the same input gray level has the same output gray level, and a larger input gray level never gives a smaller output gray level.

Reading the check. \(D\) must be much smaller for the equalized image than for kids.png, but it is not 0. The number of distinct gray levels can stay the same or fall, but it can never rise. If it rises, the function is not a pointwise operation.

Step 5: Contrast Stretching

Contrast stretching maps the gray levels from 0 to \(T_1\) to 0 (black), maps the gray levels from \(T_2\) to 255 to 255 (white), and stretches the gray levels between \(T_1\) and \(T_2\) linearly over the full range:

$$ f(x) = \begin{cases} 0 & x \le T_1 \\ 255 \, \dfrac{x - T_1}{T_2 - T_1} & T_1 < x < T_2 \\ 255 & x \ge T_2 \ , \end{cases} $$

rounded to the nearest integer. The figure shows the map.

The contrast stretching map.

If a pointwise operation \(y = f(x)\) is one to one, then the input and output histograms are approximately related by

$$ h_{\text{out}}(y) \approx \left. \frac{h_{\text{in}}(x)}{|f'(x)|} \right|_{x = f^{-1}(y)} \ , \tag{4} $$

where \(f^{-1}(y)\) is rounded to the nearest integer. The map \(f\) is not one to one, because it sends whole ranges to 0 and to 255, so the output histogram can have spikes at 0 and 255. Between the thresholds \(f'\) is the constant \(255/(T_2 - T_1)\). So between 1 and 254 the output histogram is a stretched and rescaled copy of the input histogram between \(T_1\) and \(T_2\). 

def stretch(x, T1, T2):
    """This function stretches the contrast of an 8-bit image.

    Gray levels at most T1 map to 0, gray levels at least T2 map to 255, and
    gray levels between them map linearly from 0 to 255.  The result is
    rounded to the nearest gray level.

    x        (H, W) uint8 NumPy array
    T1, T2   ints with 0 <= T1 < T2 <= 255
    returns  (H, W) uint8 NumPy array, the stretched image
    """

Step 6: Gamma

A display does not produce light in proportion to the gray level it is sent. For a long time most displays were cathode ray tubes (CRTs), in which the light intensity \(I\) is a power of the applied voltage \(V\),

$$ I = V^{\gamma} \ . $$

The exponent is the gamma \(\gamma\) of the display, and a typical CRT has \(\gamma\) near 2.5. Liquid crystal and OLED displays work by different physics, but they use tables that give them a similar power law response. Most current displays follow the sRGB standard, whose response is close to a power law with \(\gamma = 2.2\). For an 8-bit gray level \(x\), the light the display produces, on the same 0 to 255 scale, is

$$ y = 255 \left( \frac{x}{255} \right)^{\gamma} \ . \tag{5} $$

Because of this power law, an image whose pixel values are proportional to light intensity looks too dark on a display, especially in the dark and middle gray levels. Gamma correction compensates for this. It applies the inverse of equation (5), which raises \(x/255\) to the power \(1/\gamma\), before the image is displayed.

There is a second reason to store images on a gamma corrected scale. The eye is more sensitive to a change in intensity on a dark background than on a bright one. When an image is quantized to 8 bits, the change in perceived brightness from one gray level to the next should be about the same everywhere. A linear scale does not do this. It gives large visible steps, called false contours, in dark regions. The gamma corrected scale happens to be close to a scale that is uniform in perceived brightness. For this reason cameras and scanners gamma correct images before they store them, and most images you see, such as JPEG photographs and video, are already on a gamma corrected scale.

Gamma matters when an image is stored on a linear scale, as in some computer graphics and scientific images, or when an image was corrected for a display whose gamma differs from yours. In this module you measure the gamma of your display and then correct two images.

Step 7: Measure the Gamma of Your Display

The measurement compares a pattern of black and white lines with a uniform gray patch. Seen from a distance, the optics of the eye blur the lines, so the pattern looks like a uniform gray. If half of the lines are white with intensity \(I_{255}\) and half are black, the pattern has intensity

$$ I_c = \frac{I_{255} + 0}{2} \ . $$

By equation (5), a uniform patch of gray level \(g\) has intensity \(I_g = I_{255} \, (g/255)^{\gamma}\). The two look the same when \(I_g = I_c\), which is when

$$ \left( \frac{g}{255} \right)^{\gamma} = \frac{1}{2} \ . \tag{6} $$

So the gray level \(g\) that matches the pattern determines \(\gamma\).

The page gamma-match.html draws the pattern. It has bands labeled lines, made of black and white lines, next to bands labeled gray, which are one solid gray. A slider sets the gray level \(g\) of the gray bands, and the page shows \(g\). At the match the bands disappear when you view the pattern from a distance. The lines can be 1 or 2 display pixels wide. The page also offers two other patterns: the same half pattern drawn as a checkerboard, and a quarter pattern with one white line in every four, whose intensity is \(I_{255}/4\). A magnifier on the page shows the pixel values around the mouse, so you can see that the lines really alternate.
